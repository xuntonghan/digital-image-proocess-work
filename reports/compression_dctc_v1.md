# Kodak 图像压缩：自研 DCTC v1 编码器

## 1. 设计目标

DCTC v1 是为课程实验实现的独立有损图像格式。它不调用 JPEG 编码器，也不是伪装成 `.jpg` 的系统库输出；仓库同时提供从 RGB 图像生成 `.dctc` 码流的编码器和只依据码流恢复 RGB 图像的解码器。

设计目标是完整展示传统变换编码的主要环节，并在与 JPEG 基线完全相同的 Kodak 24 图、4:2:0 和 Q30/Q50/Q70/Q90 设置下进行评价。

## 2. 编解码流程

编码流程如下：

1. 将 8-bit RGB 转换为全范围 YCbCr；
2. Y 保持原尺寸，Cb/Cr 以 2×2 均值执行 4:2:0 色度抽样；
3. 每个分量使用边界复制补齐到 8×8 整数块；
4. 像素减 128 后执行正交二维 8×8 DCT；
5. 使用 JPEG 标准亮度/色度量化表，并依据 Q 值缩放；
6. 量化系数按 Zigzag 顺序排列；
7. DC 系数做块间差分，AC 系数做零游程编码，带符号值使用可变长整数；
8. 三个分量的系数流再以 zlib/DEFLATE 进行熵压缩；
9. 写入带版本号、尺寸、质量、抽样方式、分量尺寸和流长度的自描述容器。

解码按相反顺序执行：容器校验、DEFLATE 解压、游程/差分恢复、逆 Zigzag、反量化、IDCT、色度上采样以及 YCbCr→RGB。程序会拒绝错误魔数、截断头部、损坏压缩流、越界系数和尺寸不一致的码流。

### DCTC v1 容器结构

| 区域 | 内容 |
|---|---|
| 5 B | 魔数 `DCTC` + 版本 `0x01` |
| 4 B | 大端序 JSON 头长度 |
| 可变 | UTF-8 JSON 元数据 |
| 可变 | DEFLATE 压缩后的 Y/Cb/Cr 系数流 |

`.dctc` 是课程自定义格式，必须使用本项目的 `decompress_dct()` 解码，不能被普通图片查看器直接打开。

## 3. 实验设置

- 数据：Kodak 24 张无损 RGB PNG；聚合 SHA256 为 `b2194c51cff99d6f3cc14fa73c0a805817b1e705abc02cf94f89165cc5e6bcc5`；
- 设置：4:2:0，Q30/Q50/Q70/Q90，DEFLATE level 9；
- 计时：预热 1 次，重复 3 次取中位数，再对 24 张图取平均；
- 范围：编解码计时不包含指标计算与结果写盘；
- 指标：PNG 文件压缩比、原始 RGB 压缩比、bpp、PSNR、SSIM、编码时间和解码时间。

## 4. DCTC 全量结果

| 质量 | DCTC 总大小 | PNG 压缩比 | 原始 RGB 压缩比 | bpp | PSNR / dB | SSIM | 编码 / ms | 解码 / ms |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| Q30 | 839,354 B | 18.341× | 33.730× | 0.712 | 30.368 | 0.8615 | 42.447 | 37.983 |
| Q50 | 1,216,482 B | 12.655× | 23.273× | 1.031 | 32.027 | 0.8968 | 54.181 | 50.786 |
| Q70 | 1,717,193 B | 8.965× | 16.487× | 1.456 | 33.740 | 0.9237 | 68.191 | 66.851 |
| Q90 | 3,336,921 B | 4.613× | 8.484× | 2.829 | 37.677 | 0.9620 | 106.296 | 116.557 |

Q70 仍是自研编码器较合理的默认折中点。Q30 适合强调体积，但细节和结构相似度下降明显；Q90 的视觉保真度最高，但压缩收益显著减小。

## 5. 与 libjpeg 基线的对比

Q 值不是跨编码器的绝对质量单位，因此最终判断应优先查看率失真曲线。由于两套实现使用同一组基础量化表，相同 Q 的并列数据仍可帮助定位实现差距：

| 质量 | DCTC 体积增加 | PSNR 差值 | SSIM 差值 |
|---:|---:|---:|---:|
| Q30 | +7.84% | −0.123 dB | −0.0036 |
| Q50 | +13.88% | −0.146 dB | −0.0028 |
| Q70 | +17.51% | −0.176 dB | −0.0022 |
| Q90 | +20.56% | −0.357 dB | −0.0013 |

DCTC 的重建质量非常接近 libjpeg，说明颜色变换、DCT、量化及逆变换实现正确；但相同 Q 下码流更大，率失真曲线整体略低于 libjpeg。主要原因是课程实现仅使用通用 DEFLATE 和简化的系数符号化，没有 JPEG 成熟的码长优化、专用 Huffman 表及大量边界优化。

速度差距更大：DCTC 是强调可读性的纯 Python/NumPy 实现，逐块游程编解码仍在 Python 循环中；libjpeg 则是经过多年 SIMD 和底层内存优化的 C 实现。因此本实验把 DCTC 定位为“算法原理和自定义码流的可验证实现”，把 libjpeg 定位为“工业性能基准”，不将两者的运行速度包装成同一成熟度。

## 6. 运行方式

```bash
dip-dct-benchmark \
  --data-dir data/compression/kodak \
  --output-dir outputs/compression/dctc_v1 \
  --qualities 30 50 70 90 \
  --subsampling 420 --entropy-level 9 \
  --repeats 3 --warmup 1 \
  --baseline-summary reports/assets/compression/jpeg_baseline/summary.json
```

命令会生成 96 个 `.dctc` 文件、96 个解压 PNG、逐图 CSV、汇总 JSON、原图/解压图对比以及 libjpeg/DCTC 率失真曲线。

## 7. 阶段结论

课程要求的图像读取、算法设计、压缩、解压、指标评价和可视化比较已经形成完整闭环。当前版本的后续优化方向是把 Python 游程循环改为向量化/编译扩展，并实现按 Kodak 统计得到的专用 Huffman 表；若需要拓展创新性，再加入学习式压缩模型，但必须继续在相同 bpp 下比较 PSNR/SSIM，不能直接比较模型内部的“质量档位”。
